# Миграции

Схема БД описана в ADR-0003 (`docs/adr/0003-db-schema.md`). Правила каталога:

- формат golang-migrate: `NNNNN_описание.up.sql` / `NNNNN_описание.down.sql` (по паре на версию),
  нумерация по возрастанию, без пропусков в уже применённых;
- миграции идемпотентны настолько, насколько это возможно (`IF NOT EXISTS`);
- применение: `make migrate PSQL_DSN=postgres://...` (обёртка над `go run ./cmd/migrate -up`),
  откат: `make migrate-down PSQL_DSN=... N=1 [YES=1]` (N обязателен, на базе без `test` в имени
  нужен `YES=1`), версия: `make migrate-version`;
- миграции встроены в бинари (`migrations.go`): `syngo-migrate` работает без каталога,
  `syngod` при старте сверяет версию схемы с последней миграцией и отказывается работать на
  непримененной, отставшей, более новой или dirty-схеме;
- интеграционные тесты: `make test-integration SYNGOD_TEST_DSN=postgres://.../syngo_test` — имя базы
  обязано содержать `test` (иначе тесты падают); поднимают схему
  с нуля, проверяют up/down, вставку события и выборку в stream-порядке;
- схема и индексы обсуждаются через pull request + ADR, если меняют модель событий/`/sync`.
