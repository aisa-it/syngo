# ADR-0001. Архитектура каркаса synapse-go

- Статус: предложено
- Дата: 2026-11-16

## Контекст

Нужен каркас Go-сервиса, на котором дальше строятся комнаты, события, `/sync` и
федерация. Требования проекта: `go vet` и `golangci-lint` без замечаний,
зелёные тесты, godoc на пакеты, ADR на отклонения от Synapse. Внешние уроки:
Dendrite потерял производительность
на polylith-архитектуре и на «`/sync` оптимизируем потом»; поэтому сразу
выбираем модульный монолит и first-class `/sync`.

## Решение

1. **Модульный монолит, один процесс.** Пакеты `cmd/syngod`, `internal/api`,
   `internal/core`, `internal/store`, `internal/config`. Один пул PostgreSQL на
   процесс. Разнесение по процессам — только как deployment-опция, не как
   структурное решение (это и был урок Dendrite: сетевые вызовы на горячем пути).
2. **Направление зависимостей `api → core ← store`.** Домен не импортирует
   `net/http` и `pgx`, поэтому логика тестируется без БД и без HTTP. Маппинг
   доменных ошибок в коды Matrix живёт в `internal/api`.
3. **Go 1.27 вместо исходно планировавшегося 1.22.** Отклонение осознанное:
   1.22 не поддерживается (последние два релиза — 1.26/1.27), а `govulncheck` на
   устаревшем toolchain сообщает десятки уязвимостей в stdlib. Компромисс —
   язык фиксируется директивой `go 1.27` в `go.mod`, образами `golang:1.27-alpine`
   в Dockerfile и CI; понижение до 1.22 потребовало бы отказаться от исправлений
   безопасности.
4. **HTTP: `chi`.** Стандартный `http.ServeMux` в Go 1.22+ умеет методы и
   wildcard'ы, но chi даёт middleware-цепочку (`RequestID`, `RealIP`,
   `WrapResponseWriter`) и группировку маршрутов под `/_matrix/client/{v3,...}`,
   которая понадобится сразу после каркаса. Зависимость одна, без транзитивных.
5. **БД: `pgx/v5` + `pgxpool`.** Нативный драйвер PostgreSQL, без `database/sql`-
   прослойки; пул с `MaxConns`/`MinConns` из конфига. Схема и миграции - ADR-0003.
6. **Конфиг: YAML + ENV, валидация до старта.** Значения по умолчанию → файл →
   окружение (секреты только в ENV/CI-переменных). `yaml.Decoder.KnownFields(true)`
   ловит опечатки в ключах, `Validate()` — невалидные значения. Секреты (DSN) не
   попадают в лог: `Config.String()` печатает `db=configured`.
7. **Логи: `log/slog` (stdlib), JSON по умолчанию.** Каждый HTTP-запрос — одна
   запись с `request_id`, статусом, размером и длительностью; `/health` — на
   уровне `debug`, чтобы не засорять лог и не влиять на стоимость наблюдаемости.
8. **Наблюдаемость с первого дня:** `GET /health` (liveness, без зависимостей) и
   `GET /health/ready` (readiness, пинг PostgreSQL, 503 при недоступности). Формат
   `/health` стабилен — по нему ходят Docker healthcheck и CI smoke-тест.
9. **Ошибки в формате Matrix уже на каркасе.** Неизвестный путь под `/_matrix/*`
   отвечает `404` + `{"errcode":"M_UNRECOGNIZED",...}`, паника в обработчике —
   `500` + `M_UNKNOWN` (а не разрыв соединения). Это дешевле сделать сразу, чем
   переделывать контракт после первого клиента.
10. **Сборка: статический бинарь в distroless.** `CGO_ENABLED=0`, `-trimpath`,
    `-ldflags "-s -w"`, финальный образ `distroless/static:nonroot` — без shell и
    пакетного менеджера.

## Соответствие Synapse

Synapse — Python/Twisted приложение с отдельными воркерами и общим PostgreSQL.
Мы сохраняем его **внешнее поведение** (CS-API, коды ошибок, семантика токенов и
порядков), но не внутреннюю структуру: сервисы Synapse — это модули Python, у нас —
пакеты Go в одном процессе. Расхождения фиксируются здесь по мере появления
функциональности; на каркасе расхождений по API нет, кроме версии спеки
(`v1.11` — заморожена на релизный цикл).

## Последствия

- Плюс: быстрые тесты без БД и без сети, простая отладка, один бинарь.
- Минус: горизонтальное масштабирование потребует вынести состояние сессий
  `/sync` в PostgreSQL/Redis (ADR-0009), решается без смены структуры
  пакетов.
- Минус: Go 1.27 требует свежих образов в CI; версия образа фиксируется, а не
  `latest`.

## Альтернативы

- **Dendrite как основа (форк).** Отклонено: проект в maintenance mode, без
  MSC4186/Sliding Sync и без кластеризации; своя кодовая база даёт контроль над
  `/sync` и state resolution, которые для нас — ключевые риски.
- **`net/http` ServeMux вместо chi.** Возможно; chi выбран ради middleware и
  группировки маршрутов, зависимость легко заменяется позже.
- **`zap` вместо `log/slog`.** Отклонено: slog в stdlib, меньше зависимостей;
  при необходимости структурных «сахаров» перейдём на `slog`-совместимые хендлеры.
